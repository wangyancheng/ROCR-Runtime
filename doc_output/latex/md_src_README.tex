To build the runtime a compatible version of the {\ttfamily libhsakmt} library and the {\ttfamily hsakmt.\+h} header file must be available. The latest version of these files can be obtained from the ROCT-\/\+Thunk-\/\+Interface repository, available here\+:

\href{https://github.com/RadeonOpenCompute/ROCT-Thunk-Interface}{\texttt{ https\+://github.\+com/\+Radeon\+Open\+Compute/\+ROCT-\/\+Thunk-\/\+Interface}}

As of ROCm release 3.\+7 {\ttfamily libhsakmt} development packages now include a CMake package config file. The runtime will now locate {\ttfamily libhsakmt} via {\ttfamily find\+\_\+package} if {\ttfamily libhsakmt} is installed to a standard location. For installations that do not use ROCm standard paths set CMake variables {\ttfamily CMAKE\+\_\+\+PREFIX\+\_\+\+PATH} or {\ttfamily hsakmt\+\_\+\+DIR} to override {\ttfamily find\+\_\+package} search paths.

As of ROCm release 3.\+7 the runtime includes an optional image support module (previously {\ttfamily hsa-\/ext-\/rocr-\/dev}). By default this module is included in builds of the runtime. The image module may be excluded the runtime by setting CMake variable {\ttfamily IMAGE\+\_\+\+SUPPORT} to {\ttfamily OFF}.

When building the optional image module additional build dependencies are required. An AMDGCN compatible clang and device library must be installed to build the image module. The latest version of these requirements can be obtained from the ROCm package repository (see\+: \href{https://rocmdocs.amd.com/en/latest/Installation_Guide/Installation-Guide.html}{\texttt{ https\+://rocmdocs.\+amd.\+com/en/latest/\+Installation\+\_\+\+Guide/\+Installation-\/\+Guide.\+html}}) The latest source for these projects may be found here\+:

\href{https://github.com/RadeonOpenCompute/llvm-project}{\texttt{ https\+://github.\+com/\+Radeon\+Open\+Compute/llvm-\/project}}

\href{https://github.com/RadeonOpenCompute/ROCm-Device-Libs}{\texttt{ https\+://github.\+com/\+Radeon\+Open\+Compute/\+ROCm-\/\+Device-\/\+Libs}}

Additionally {\ttfamily xxd} must be installed.

The runtime optionally supports use of the cmake user package registry. By default the registry is not modified. Set CMake variable {\ttfamily EXPORT\+\_\+\+TO\+\_\+\+USER\+\_\+\+PACKAGE\+\_\+\+REGISTRY} to {\ttfamily ON} to enable updating the package registry.

HSA Platform System Architecture Specification 1.\+1\hypertarget{md_src_README_autotoc_md18}{}\doxysection{Runtime Design Overview}\label{md_src_README_autotoc_md18}
The AMD ROC runtime consists of three primary layers\+:


\begin{DoxyItemize}
\item C interface adaptors
\item C++ interfaces classes and common functions
\item AMD device specific implementations
\end{DoxyItemize}

Additionally the runtime is dependent on a small utility library which provides simple common functions, limited operating system and compiler abstraction, as well as atomic operation interfaces.\hypertarget{md_src_README_autotoc_md19}{}\doxysection{C Interface Adaptors}\label{md_src_README_autotoc_md19}
Files\+:


\begin{DoxyItemize}
\item {\ttfamily hsa.\+h}(cpp)
\item {\ttfamily \mbox{\hyperlink{hsa__ext__interface_8h}{hsa\+\_\+ext\+\_\+interface.\+h}}}(cpp)
\end{DoxyItemize}

The C interface layer provides C99 APIs as defined in the HSA Runtime Specification 1.\+1. The interfaces and default definitions for the standard extensions are also provided. The interface functions simply forward to a function pointer table defined here. The table is initialized to point to default definitions, which simply return an appropriate error code. If available the extension library is loaded as part of runtime initialization and the table is updated to point into the extension library.\hypertarget{md_src_README_autotoc_md20}{}\doxysection{C++ Interfaces Classes \& Common Functions}\label{md_src_README_autotoc_md20}
