\doxysubsection{Detailed Description}
A memory pool encapsulates physical storage on an agent along with a memory access model. 

A memory pool encapsulates a physical partition of an agent\textquotesingle{}s memory system along with a memory access model. Division of a single memory system into separate pools allows querying each partition\textquotesingle{}s access path properties (see \mbox{\hyperlink{inc_2hsa__ext__amd_8h_a1a839a4273411c5a1812f72d170fbdc8}{hsa\+\_\+amd\+\_\+agent\+\_\+memory\+\_\+pool\+\_\+get\+\_\+info}}). Allocations from a pool are preferentially bound to that pool\textquotesingle{}s physical partition. Binding to the pool\textquotesingle{}s preferential physical partition may not be possible or persistent depending on the system\textquotesingle{}s memory policy and/or state which is beyond the scope of HSA APIs.

For example, a multi-\/node NUMA memory system may be represented by multiple pool\textquotesingle{}s with each pool providing size and access path information for the partition it represents. Allocations from a pool are preferentially bound to the pool\textquotesingle{}s partition (which in this example is a NUMA node) while following its memory access model. The actual placement may vary or migrate due to the system\textquotesingle{}s NUMA policy and state, which is beyond the scope of HSA APIs.
