58 // ROCr allows users to filter and reorder various Gpu devices that are
59 // present on ROCm system. This ability is made available via environment
60 // variable ROCR_VISIBLE_DEVICES (RVD). Users are allowed to specify a list
61 // of Gpu Identifiers separated by comma delimiter as the value of this env
62 // variable.
63 //
64 // On a ROCm platform instance, a Gpu device could be identified by its:
65 //
66 // Index - Position at which ROCr reports it upon device enumeration
67 // UUID - A string that is unique and is immutable i.e. tags Gpu
68 // instance across systems and power cycles. UUID values
69 // are defined to begin with "GPU-" prefix
70 //
71 // @note: Not all Gpu devices will report valid UUID's. For example,
72 // Only devices from Gfx9 and later will encode valid UUID's. To account
73 // for this and other reasons, the UUID string "GPU-XX" is defined as
74 // indicating those devices. Users can still select those Gpu devices
75 // by using their enumeration index
76 //
77 // Users are allowed to select a device by specifying its UUID string in
78 // full or part. A UUID string that does not uniquely match an agent's
79 // valid UUID prefix is interpreted as terminating. The UUID string
80 // "GPU-XX" will not match and therefore will terminate
81 //
82 // RVD interpreter treats an empty token list as filtering all devices.
83 // Users can use this mode to report ZERO Gpu devices
84 //
85 // RVD interpreter treats a token as Illegal if can't be evaluated into an
86 // instance of Device UUID or Enumeration Index
87 //
88 // RVD interpreter treats a Legal instance of Enumeration Index as Terminating
89 // if any ONE of the following conditions apply:
90 // Value of index lies outside the interval [0 - (numGpuDevices - 1)]
91 // Value of index maps to a device that has been previously selected
92 //
93 // RVD interpreter treats a Legal instance of Device UUID as Terminating
94 // if any ONE of the following conditions apply:
95 // Value of UUID is the literal "GPU-XX"
96 // Value of UUID matches ZERO devices on system
97 // Value of UUID matches TWO or more devices on system
98 // Value of UUID maps to a device that has been previously selected
99 //
100 // RVD interpreter builds the list of Gpu devices to surface using tokens
101 // that are Legal and NOT Terminating
102 //
103 // Following are some examples of RVD value strings and their intepretation
104 // on a ROCm system with four Gpu devices. Assume for now the UUID's of the
105 // four Gpu devices are:
106 // Gpu-0: "GPU-BABABABABABABABA"
107 // Gpu-1: "GPU-ABBAABBAABBAABBA"
108 // Gpu-2: "GPU-BABAABBAABBABABA"
109 // Gpu-3: "GPU-ABBABABABABAABBA"
110 //
111 // Surface ZERO devices
112 // A1) ROCR_VISIBLE_DEVICES=""
113 // A2) ROCR_VISIBLE_DEVICES="-1"
114 // A3) ROCR_VISIBLE_DEVICES="GPU-XX"
115 //
116 // Surface Gpu-3 and Gpu-0 devices in that order
117 // B) ROCR_VISIBLE_DEVICES="3,GPU-BABABABABABABABA,4"
118 //
119 // Surface Gpu-1 and Gpu-2 devices in that order
120 // C) ROCR_VISIBLE_DEVICES="1,GPU-ABBAABBAABBAABBA,GPU-XX"
121 //
122 // Surface Gpu-3 and Gpu-2 devices in that order
123 // D) ROCR_VISIBLE_DEVICES="3,GPU-BABAABBA,GPU-XX"
124 //
